# 神輿なう 🎉

お神輿（みこし）の現在位置・運行状況をリアルタイムに共有する **Google Apps Script (GAS) 製 Web アプリ**です。

- **閲覧画面（Viewer）**: お神輿の現在位置を地図で表示し、休憩所の通過状況・遅延などを誰でも確認できます
- **役員用操作画面（Admin）**: パスワード認証付きで、休憩所の到着・出発や GPS 自動追尾を記録します

データの保存先は Google スプレッドシートなので、専用サーバーは不要です。

## セットアップ

### 1. スプレッドシートの準備

Google スプレッドシートを新規作成し、**以下のシートを正確な名前で**用意します。

| シート名 | 列構成 | 説明 |
| --- | --- | --- |
| `GPSログ` | A=タイムスタンプ, B=緯度, C=経度, D=GEO文字列 | お神輿の位置ログ |
| `休憩所マスター` | A=id, B=名前, C=予定到着, D=予定出発, E=緯度, F=経度 | 休憩所の一覧と予定時刻・座標 |
| `休憩所記録` | A=記録日時, B=休憩所名, C=到着/出発, D=コメント, E=未使用 | 到着・出発の実績ログ |
| `トイレマスター` | A=id, B=名前, C=緯度, D=経度 | トイレの一覧と座標 |

- 1行目はヘッダー行、データは2行目以降に書きます
- 「休憩所マスター」の予定時刻は `HH:mm` 形式（例: `10:30`）で入力します
- 座標を空欄にすると、その場所は地図にピンが出ません（タイムライン表示のみ）

### 2. GAS プロジェクトの作成とコード配置

1. スプレッドシートのメニューから **拡張機能 → Apps Script** を開く
2. プロジェクトを「神輿なう」などにリネーム
3. `code.gs` / `Viewer.html` / `Login.html` / `Admin.html` をそれぞれ新規作成して、本リポジトリの内容を貼り付ける

> 注意: `Admin.html` というファイル名は、`HtmlService.createHtmlOutputFromFile('Admin')` と対応しています。ファイル名（大文字小文字含む）を変える場合は `code.gs` 側も合わせて変更してください。
> また `index.html`（ラッパー）は GitHub Pages 用であり、**GAS プロジェクトには入れないでください**。GAS のファイル名は大文字小文字を区別しないため、`index.html` を入れると役員用の `Admin.html`（旧 `Index.html`）と衝突して上書きされてしまいます。

### 3. スクリプトプロパティの設定

GAS エディタの **プロジェクトの設定 → スクリプトプロパティ** で以下を追加します。

| キー | 値 | 説明 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 任意のパスワード | 役員用操作画面のログインに使用 |
| `GMAP_API_KEY` | Google Maps API キー | 閲覧画面の地図表示に使用 |

> パスワードや API キーをコードに直書きせず、必ずスクリプトプロパティで管理します。

### 4. Google Maps API の準備

- [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成し、**Maps JavaScript API** を有効化
- API キーを作成し、上記の `GMAP_API_KEY` に設定
- API キーの制限で、ご自身の Web アプリの URL（`script.google.com` 配下）を許可しておくのが推奨

### 5. Web アプリとしてデプロイ

1. GAS エディタ右上の **デプロイ → 新しいデプロイ**
2. 種類として **ウェブアプリ** を選択
3. **アクセスできるユーザー: 全員（匿名ユーザーを含む）** に設定
4. デプロイすると発行された Web アプリ URL が「閲覧画面」になります

### 6. （任意）「Google Apps Script のユーザーによって作成されました」バナーを隠す

GAS の Web アプリ（匿名公開）のページ上部には、Google が自動で **「このアプリケーションは Google Apps Script のユーザーによって作成されました」** という警告バナーを挿入します。これはコードでは消せませんが、**通常の Web ページの iframe で Web アプリを表示する**ことで、閲覧者にはバナーを見せずに済みます。

本リポジトリの `index.html` がラッパー（親ページ）です。以下の手順で GitHub Pages に配置します。

#### 6-1. GitHub リポジトリの準備

- GitHub にリポジトリを作成し、本リポジトリのファイル（`index.html`・`code.gs`・`Viewer.html` など）をプッシュする
- リポジトリは公開（public）である必要があります（無料アカウントの場合）

#### 6-2. GitHub Pages を有効化

1. GitHub のリポジトリページで **Settings → Pages** を開く
2. **Build and deployment** の **Source** で **Deploy from a branch** を選択
3. **Branch** を **main** / **`/ (root)`** に設定して **Save**
4. しばらくすると `https://<ユーザー名>.github.io/<リポジトリ名>/` でサイトが公開されます（初回は最大 10 分程度かかります）

#### 6-3. 動作確認と QR コードの更新

1. `https://<ユーザー名>.github.io/<リポジトリ名>/` にアクセスし、バナーなしで閲覧画面が表示されることを確認
2. `index.html` の `GAS_APP_URL` に、デプロイした Web アプリ URL（閲覧画面）が設定されていることを確認済みかチェック（未設定なら書き換える）
3. `Flyer.html` の `APP_URL` を GitHub Pages の URL（上記）に変更して QR コードを再発行
4. `code.gs` には `setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL)` が追加済みなので、変更後は GAS を**再デプロイ（新しいバージョン）** してください

> 注意: バナー自体は Google が挿入するもので、完全に削除はできません。iframe 方式は「親ページからは見えなくする」回避策です。
> 一部の環境（Safari のプライベートブラウズ等）では iframe 内でもバナーが表示されることがあります。

## 使い方

### 閲覧画面（一般公開）

GitHub Pages の URL（または Web アプリ URL）にアクセスすると表示される画面です。

- 🗺️ **地図**: お神輿の現在位置（金と紅のアイコン）を自動追従。休憩所は赤ピン、トイレは青ピンで常時表示
- 📊 **ステータスカード**: 現在の状況を「移動中」「休憩中」「渡御終了」の3状態で色分け表示（遅延/巻きも表示）
- 🥤 **休憩所タブ**: 各休憩所の予定時刻・実際の到着/出発時刻・コメント・進行バッジ（予定/次の休憩所/滞在中/通過済）を一覧表示
- 🚻 **トイレタブ**: トイレの一覧を表示
- 📍 **ピンをタップ**: 確認ダイアログ後に Google マップアプリ / 地図サイトで場所を開く
- 🔄 データは **30秒ごとに自動更新**（ヘッダーの「再読み込み」で手動更新も可能）

### 役員用操作画面

**GitHub Pages の URL** に `?mode=admin` を付けてアクセス（例: `https://<ユーザー名>.github.io/<リポジトリ名>/?mode=admin`）。ラッパーがクエリパラメータを GAS アプリへ引き継ぎます（Web アプリ URL 直アクセスの場合は `https://script.google.com/macros/s/xxx/exec?mode=admin`）。

- 初回は `Login.html` が表示されるので、`ADMIN_PASSWORD` に設定したパスワードでログイン
- ログイン後は 12 時間有効なセッショントークンが発行され、`Admin.html`（操作画面）が表示される

操作画面でできること:

1. **① 休憩所の通過記録**
   - 休憩所を選択して「到着」「出発」を記録（コメントも入力可）
   - 到着済みの休憩所は到着ボタンが無効になり、出発後は次の休憩所へ自動移動（打ち間違い防止）
2. **② 位置情報（GPS）自動送信**
   - 「自動追尾をスタート」すると **3分ごと** に現在地を `GPSログ` シートへ記録
   - 「自動追尾を停止」で停止

### 外部からの GPS 送信（POST API）

`doPost` を使って、ショートカットアプリなどからも GPS を記録できます。

```bash
# 例: curl で現在地を送信
curl -X POST -H "Content-Type: application/json" \
  -d '{"lat": 35.38858, "lng": 139.403229}' \
  https://script.google.com/macros/s/xxxxx/exec
```

成功時は `{"status": "success", "lat": ..., "lng": ..., "geo": ...}` が JSON で返ります（`GPSログ` シートに追記されます）。

### iPhone ショートカットでの GPS 定期送信

ブラウザの GPS 自動追尾（`Admin.html`）は画面を閉じると止まりますが、iPhone の「ショートカット」アプリから同じ `doPost` を呼び出せば、**実行中は画面を開いたまま**、定期的に現在地を送信できます。

#### ショートカットの組み立て方

1. **ショートカット** アプリを開き、新しいショートカットを作成
2. 「**現在地を取得**」アクションを追加
3. 「**URLの内容を取得**」アクションを追加し、以下のように設定:
   - **URL**: Web アプリの URL（例: `https://script.google.com/macros/s/xxxxx/exec`）
   - **方法**: `POST`
   - **本文を要求**: `JSON` を選択
   - 「新規フィールド」を2つ追加:

     | フィールド名 | 値 |
     | --- | --- |
     | `lat` | 現在地を取得 → **緯度** |
     | `lng` | 現在地を取得 → **経度** |

     > ⚠️ フィールド名は必ず **`lat` / `lng`** にしてください。`code.gs` の `doPost` は `contents.lat` / `contents.lng` を読み取るため、名前が違うとエラーになります（`lng` は経度の略で、`longitude` ではない点にも注意）

4. 「**待機**」アクションを追加（例: 30 秒）
5. 手順 2〜4 を「**繰り返す**」で囲み、回数を設定（例: 60 回）

完成イメージ（60 回 × 30 秒待機の場合）:

```
[繰り返す] 60 回
  ├─ 現在地を取得
  ├─ URLの内容を取得（POST /exec）
  └─ 待機（30秒）
```

これで「位置送信 → 30秒待機 → 位置送信 → …」が設定回数だけ繰り返され、`GPSログ` シートに現在地が記録され続けます。

> 💡 実行時間はおおよそ **「回数 × 待機秒数」** です（例: 60回 × 30秒 ≒ 30分間）。送りたい時間に合わせて回数と秒数を調整してください。

#### 動作確認

ショートカットを手動で実行し、スプレッドシートの「GPSログ」シートに 1 行追記されることを確認します。確認できたら「繰り返す」の回数と「待機」の秒数を本番用に調整してください。

#### 注意点

- **待機は「繰り返す」の内側の最後**に入れる（送信 → 待機 の順にする）
- iOS はバックグラウンド実行が止められることがあるため、**実行中はショートカットの実行画面を表示したまま**にするのが確実です
- 送信先は必ず **`/exec` の Web アプリ URL** を使ってください（`/dev` はテスト用で開発者本人以外アクセスできません）
- 1 回の送信で GAS 側の処理に数秒かかることがあります（初回のリダイレクト処理など）

## ファイル構成の詳細

### `code.gs`（バックエンド）

- `doGet(e)` — パラメータ `mode=admin` とセッショントークンの有無で、閲覧画面 / ログイン画面 / 操作画面を振り分け
- `login(password)` — パスワード検証とセッショントークン発行（有効期限 12 時間、`CacheService` に保存）
- `doPost(e)` — JSON（緯度・経度）を受け取り `GPSログ` に追記
- `getStations()` — 休憩所一覧（記録済み状態つき）を返す（操作画面用）
- `recordStation(data)` — 到着/出発を `休憩所記録` に追記
- `recordGPS(data)` — GPS 座標を `GPSログ` に追記
- `getViewerData()` — 閲覧画面用の全データ（最新 GPS・休憩所・トイレ・タイムライン・遅延計算）を組み立てて返す
- `getGmapApiKey()` / `getAdminPassword()` — スクリプトプロパティからキー・パスワードを取得

**遅延計算の仕組み**: 遅延は「現在時刻」ではなく、**直近の記録（到着/出発）を打った時刻と予定時刻の差**から算出します。そのため休憩中・移動中でも遅延値が刻々と増え続けることはありません。

## スプレッドシートのシート構成

```
[スプレッドシート]
├─ GPSログ         … お神輿の位置ログ（自動送信・POST で追記）
├─ 休憩所マスター  … 休憩所のマスター（予定時刻・座標）※事前入力
├─ 休憩所記録      … 到着/出発の実績ログ（操作画面で追記）
└─ トイレマスター  … トイレのマスター（座標）※事前入力
```

## 注意事項・制限

- **認証は操作画面のみ**: 閲覧画面は誰でもアクセスできる公開情報として扱っています
- **操作画面のログインはシンプルなパスワード方式**: 本格的なユーザー管理は行いません。管理者パスワードは十分に強力なものを設定してください
- **GPS 自動送信はブラウザが開いている間のみ**: スマホの画面が閉じられると送信が止まります（バッテリー最適化の影響も受けます）。長時間の追尾が必要な場合は、[iPhone ショートカットでの GPS 定期送信](#iphone-ショートカットでの-gps-定期送信) を参照してください
- **スプレッドシートの規模**: ログが大量に増えると取得・描画が遅くなるため、祭り期間後に `GPSログ` の古い行を削除するなどのメンテナンスが有効です
- **タイムゾーン**: 時刻は JST（日本標準時）基準でフォーマットしています
- **警告バナー**: 匿名公開の GAS Web アプリには Google が「このアプリケーションは Google Apps Script のユーザーによって作成されました」バナーを自動挿入します。コードでは消せないため、隠したい場合は [`index.html`](#6-任意google-apps-script-のユーザーによって作成されましたバナーを隠す)（GitHub Pages ラッパー）の iframe 方式を使います
